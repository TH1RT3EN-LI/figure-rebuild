# 图片预览采样修复与逐项复核

本轮修复 CPU 预览在大幅缩小图片时丢失细线、产生硬边的问题，并重新构建、检查 22 张受影响的完整图。新增关闭 23 项：19 项预览采样、Fawkes 的直接原生 PNG 接缝，以及 ZeRO 一项、Entangled 两项原问题。原清单累计 190/296 项关闭，106 项开放；71 项后续发现中 26 项解决、45 项开放，共 151 项开放。关闭层为模型可见性审阅，用户验收仍为 pending。

## 共用能力

实际 Skia Canvas 3.0.8 控制发现，`imageSmoothingQuality` 三档产生相同像素，80 像素条纹一次缩小到 10 像素会漏掉部分细线。新增[完整源窗口分阶段缩小](../../references/preview-image-sampling.md)策略，按包含旋转、剪切的源像素到设备像素变换选择阶段，每次每轴最多减半。原倍率预览直接使用过滤后的单个图片；4x 整图缩小得到的 smooth 1x 辅助图继续单列，未用于问题验收。

过滤保留完整源窗口和 alpha，在最后一次绘制使用原目标框及原上下文的裁切、透明度和合成状态。不缓存可变化的 Canvas/Image。单阶段最多 16M 像素、每轴 32768、单次绘制累计最多 24M 像素和 16 阶段，先规划后分配；这不是整个外部渲染进程的总内存界。显式关闭平滑及未支持的绘制参数保持原方法。裁切源窗口不预过滤，防止裁切外的墨迹混入边缘，实际审计计数并保留复核限制。

NetLock、ALEX CDF、Fawkes、ZeRO、SAM 和 LLaVA 六图中的选定图片，另使用已有显式原生 occurrence 接口生成 4x 来源素材。保留原 PDF 的 CTM、真实 clip/mask 和透明整数框，绑定文件摘要、页码、ROI、实例序号及完整回执。新素材在最终 PPT 中核对字节、框、零裁剪及全场景顺序；非图片对象保持原来源。这是有来源回执的新素材选择，没有扩大原生上下文准入范围。

完整曲线证明回执也改为流式紧凑 JSON，保留全部字段和数字类型。实际 Ansor / CoCoNuT 回执分别从 611,658,555 / 574,926,797 字节降到 294,013,119 / 276,371,775 字节，解决本次 Node 单字符串上限引起的构建失败。对两份真实旧大回执调用维护写入器，再读回逐字段、值和精确内置类型比较，全部一致。不同新构建的原始整形状 XML 摘要含新生成的 creation GUID，不能要求整份回执跨构建相同；这两例只有 `initial_shape_sha256` 不同，来源、几何及数值证明字段不变。未删减数学证据，也未声称支持任意大小的 JSON。
